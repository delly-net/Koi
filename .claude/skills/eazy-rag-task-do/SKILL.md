# 任务计划执行

此技能用于对 EAZY.RAG 知识库当前项目「Koi项目」（项目 ID: 9）中已有执行计划的任务，按最新执行计划执行相关操作，操作完成后将执行结果回写（confirm_execution），更新任务状态，并将执行结果展示到对话中。

**本技能自包含「补充说明 → 升版 → 执行」全链路**：最新执行计划版本含补充说明（正文已冻结，即「补充说明未 replan」）时，由本技能**先按第 4 步内联的「计划重新生成」流程升版**生成新版本，再以升版后的最新版本为准执行；**无需用户另行运行 `/eazy-rag-task-replan`，也不得按冻结的旧版本执行**。本技能**执行前不展示计划正文、不等待用户确认**，读取（或升版后重读）最新版本后直接执行。

## 使用方法

```
/eazy-rag-task-do {任务Id}
```

任务 ID 由参数 `{任务Id}` 提供或从上下文识别；未提供且无法识别时，按「确定目标任务 ID」步骤读取当前模块下非已归档任务列表供用户选择。

## 功能

1. **确定目标任务 ID**：任务 ID 由参数或上下文识别；若无法识别，使用 `/eazy-rag-module-get` 获取当前工作模块；若未设置（无值），先运行 `/eazy-rag-module-set` 设置当前工作模块；随后调用 `mcp__eazy-rag__list_tasks`（moduleId=当前模块Id）读取当前模块下**所有非已归档任务**列表，经 AskUser 询问用户选择目标任务。
2. **读取任务与最新执行计划**：
   - 调用 `mcp__eazy-rag__get_task`（taskId）→ 任务名称/描述/状态，校验任务归属当前项目且未归档；
   - 调用 `mcp__eazy-rag__get_execution_plan`（taskId，默认最新版本）→ 最新执行计划正文 + 执行结果 + 该版本补充说明 + **返回的 planId**（供回写执行结果使用）与 **shareCode**（供输出分享查阅链接使用）。
3. **判断任务与计划状态（决定是否先行升版）**：
   - 任务状态为 **Archived** → **拒绝执行**（已归档任务只读，不得执行）；
   - 最新版本**含补充说明**（supplementaryNotes 非空）→ 属「补充说明未 replan，正文已冻结」，**不可直接执行**：**先执行第 4 步「计划重新生成」内联升版**，升版完成后**必须回到第 2 步重新读取最新版本**（拿到新版本的正文、planId 与 shareCode），再进入第 5 步执行；**严禁按冻结的旧版本执行**；
   - 最新版本**已执行**（IsExecuted=true）→ 已有执行结果：向用户说明并询问是**复用既有执行结果**，还是**先升版重做**；二者择一后继续，不得静默跳过；
   - 其余情况 → 状态正常，直接进入第 5 步执行。
4. **计划重新生成（内联 `/eazy-rag-task-replan` 全流程；仅在「最新版本含补充说明」时执行，否则整节跳过）**：
   4.1 **读取版本历史与补充说明**：调用 `mcp__eazy-rag__list_execution_plan_versions`（taskId）→ 所有版本的元信息与补充说明（**不含执行计划正文**），据此确认本次待消化的补充说明；
   4.2 **提取新的补充关键词**：基于任务描述、最新执行计划、执行结果与本次补充说明，提取/联想**新的补充关键词**（新增功能点、领域词、技术词等），用于后续检索；
   4.3 **搜索关联已归档任务**：调用 `mcp__eazy-rag__search_archived_tasks`（projectId=9，keywords=关键词）搜索关联已归档任务信息，作为参考；
   4.4 **搜索项目专属记忆库记忆点**：调用 `mcp__eazy-rag__search_memory`（projectId=9，keywords=**第 4.2 步同一批关键词**）检索该项目**专属记忆库**中的历史记忆点（在记忆点标题/内容中匹配，按命中关键词数降序、同分按更新时间倒序，最多 10 条；直接命中不足时用同库双向关联记忆点补全）；取回的记忆点作为后续**分析思考**的**待分析信息之一**（历史约定、既有决策、踩坑经验等）。**调用失败（项目暂无专属记忆库、无访问权、关键词全空等）或返回 0 条时静默跳过并继续**，不报错、不中断、不打扰用户；
   4.5 **关键词工具搜索本地文件**：直接使用关键词工具（Grep/Glob）搜索本地项目文件，寻找可复用实现与既有模式；
   4.6 **分析思考**：结合任务现状（既有执行计划/历史执行结果/补充说明）与搜集到的信息，并纳入**第 4.4 步取回的记忆点**，识别关键设计决策、与既有计划的差异点及不确定点；
   4.7 **AskUser 提问**：仅对无法确定的信息向用户提问——**所有问题都必须提供备选项**（AskUserQuestion 带 options）；提问时调用 `mcp__eazy-rag__add_task_question`（taskId，question，options JSON 数组）将问题实时存储到任务问答子表；用户回答后调用 `mcp__eazy-rag__answer_task_question`（taskId，questionId，answer）记录回答；所有提问经操作日志在**执行历史**中展示；
   4.8 **生成 MD 格式执行计划**：结合所有信息重新生成执行计划，包含章节：任务描述/任务分析/执行步骤/执行输出/结果验收/参考文档/执行规范/注意事项；**须包含完整的原有执行计划内容**，并在原有基础上用**【新增】【修改】【移除】**文字标签标明相对既有版本的差异（保留适用内容，更新变更部分）；
   4.9 **保存为新版本执行计划**：调用 `mcp__eazy-rag__save_execution_plan`（taskId，content，forceNewVersion=true）——**始终创建新版本**（版本号递增）、不覆盖既有版本、完整保留版本历史；从返回中取**新版本的 planId 与 shareCode**（供回写执行结果与输出分享链接使用）；有可参考的已归档/历史任务时传入 relatedTaskIds（关联历史任务 Id 的 JSON 数组）；
   4.10 **输出执行计划概要**：**不向用户展示执行计划完整正文**，仅输出「执行计划概要」——任务名称、本次新版本号、新版本各章节标题清单、以及相对上一版本的**【新增】【修改】【移除】**变更点摘要（每条一行，总计 ≤ 10 条），随后按第 8 步同款口径输出分享查阅链接；**仅输出，不等待用户确认**，随后**回到第 2 步重新读取最新版本**并继续第 5 步。
5. **按执行计划执行操作**：**不再向用户展示执行计划正文、也不再等待用户确认**，直接依据最新版本执行计划的「执行步骤」「执行输出」章节在本地（当前项目工作目录）执行相关操作（代码修改、文件读写、检索等）；执行时可调用 `mcp__eazy-rag__search_documents` / `mcp__eazy-rag__get_document` 检索参考文档，使用 Grep/Glob 搜索本地文件辅助。
6. **回写执行结果**：执行完成后调用 `mcp__eazy-rag__confirm_execution`（taskId，planId=最新执行计划的 planId，executionResult=执行结果内容）将 AI 执行结果保存到该执行计划版本，并把任务状态置为已执行（Executed）。
7. **更新任务状态**：回写执行结果后任务状态自动置为 Executed；若任务已全部完成，可调用 `mcp__eazy-rag__update_task`（taskId，status=Completed）将任务状态更新为已完成。
8. **展示执行结果**：将执行结果（执行摘要/关键产出/完成情况）展示到对话中；**执行完成后（含复用既有执行结果的情形，只要流程走到本步）同时输出分享查阅链接**：用最新版本的 `shareCode`（未升版时即第 2 步 `get_execution_plan` 返回的 `shareCode`；触发第 4 步升版时为升版后重读的最新版本 `shareCode`）拼接 `https://rag.jueyun.net/share/{分享码}`，以 Markdown 超链接 `[分享查阅]({完整URL})` 输出。

## 注意事项

- 所有 MCP 调用必须携带正确的项目 ID：9。
- **所有步骤非注明需要询问或确认时，无需询问和确认，直接执行**。
- **目标任务必须属于当前项目且未归档**：调用 `mcp__eazy-rag__get_task` 校验任务归属；已归档任务不允许执行。
- **执行前无需展示计划、无需等待确认**：读取（或升版后重读）最新执行计划后**直接执行**；本技能唯一的执行前询问仅出现在「最新版本已执行」分支（复用既有结果或升版重做二选一）。
- **含补充说明先由本技能内联升版再执行**：最新执行计划含补充说明（正文已冻结）时**不可直接执行**，须由**第 4 步内联的「计划重新生成」流程**升版生成新版本，随后**回到第 2 步重读最新版本**再执行；**无需用户另行运行 `/eazy-rag-task-replan`**，也**严禁按冻结版本执行**。
- **升版必须为新版本**：第 4.9 步调用 `save_execution_plan` 时须传 `forceNewVersion=true`，确保创建新版本（版本号递增）、不覆盖既有版本。
- **先确定任务 ID 再操作**：任务 ID 由参数/上下文提供；无法识别时须读取模块下**非已归档任务**列表供用户选择，禁止猜测任务 ID。
- **执行结果必须回写落库**：执行完成后必须调用 `confirm_execution` 回写执行结果（记录到执行计划并置任务状态为 Executed），不得仅展示而不落库；回写时 planId 取第 2 步 `get_execution_plan` 返回的 planId（触发升版时为升版后重读的最新版本 planId）。
- **分享查阅链接**：分享码取自第 2 步 `get_execution_plan` 返回的 `shareCode`（**不要从 `confirm_execution` 取，它不返回分享码**）；**若本次触发了第 4 步升版，则取升版后回到第 2 步重读的最新版本 shareCode**（新分享码由 `save_execution_plan` 生成）。用它拼接分享查阅 URL `https://rag.jueyun.net/share/{分享码}` 并以超链接输出，供用户在浏览器查看刚执行的版本（前端访问地址已由系统配置「系统外部网址」在技能下载时填充）。**执行不会改变分享码**：`confirm_execution` 原地修改该版本，不新建版本、不重新生成分享码，故取到的分享码执行后依然有效，**切勿重新生成**。
- **内联升版不得丢失 replan 既有约束**：AskUser 提问必带 options、问答经 `add_task_question` / `answer_task_question` 实时入库并写操作日志、新版本须含全部章节且**完整保留原有执行计划内容**并标注【新增】【修改】【移除】差异、记忆点不可用即静默跳过。
- **本技能自包含升版能力**：`/eazy-rag-task-replan` 仍可用于「仅重新生成计划、不执行」的场景；本技能需要升版时**不再外调该技能**，而是按第 4 步内联完成。
